# AI Context

[Read in english](README.md)

Компактный шаблон для организации кодовой базы, который помогает ИИ-агентам находить **минимум контекста, необходимый для задачи**, и не привязан к конкретному инструменту.

Шаблон намеренно небольшой и не навязывает язык, фреймворк, архитектуру или поставщика ИИ. Его можно адаптировать для фронтенда, бэкенда, мобильной разработки, работы с данными, инфраструктуры, микросервисов или монорепозиториев.

## Пять принципов

1. **Минимум постоянного контекста** — глобальные инструкции должны быть короткими.
2. **Постепенная загрузка контекста** — проект → домен/сервис → задача → пример → исходный код.
3. **Меньше поисковой работы** — предоставляйте карты проекта, точки входа и эталонные примеры.
4. **Повторное использование знаний** — сохраняйте результаты трудоёмкого исследования для следующих задач.
5. **Чистота контекста** — удаляйте устаревшую, дублирующуюся и вводящую в заблуждение информацию.

## Быстрый старт

Скопируйте в свой репозиторий:

```text
AGENTS.md
docs/
skills/                  # необязательно
AI_CONTEXT_CHECKLIST.md
```

Затем:

1. Замените `[заполнители]` реальными значениями.
2. Удалите разделы, которые не относятся к вашему проекту.
3. Сохраняйте `AGENTS.md` коротким.
4. Заполните `docs/project-map.md`.
5. Добавьте 2–5 реальных эталонных примеров.
6. Добавляйте локальные файлы `AGENTS.md` только там, где полезны дополнительные правила.
7. Создавайте навыки только для повторяющихся рабочих процессов.
8. Пройдитесь по `AI_CONTEXT_CHECKLIST.md`.

## Рекомендуемая структура

```text
your-project/
├── AGENTS.md
├── AI_CONTEXT_CHECKLIST.md
├── docs/
│   ├── architecture.md
│   ├── project-map.md
│   └── workflows.md
├── skills/
│   ├── README.md
│   └── example-task/
│       └── SKILL.md
└── ...
```

## Модель загрузки контекста

```text
Задача
  ↓
Минимальный глобальный контекст
  ↓
Контекст нужного домена / сервиса
  ↓
Инструкции для конкретной задачи
  ↓
Эталонный пример
  ↓
Целевой поиск
  ↓
Минимум необходимого исходного кода
  ↓
Изменение + целевая проверка
```

Не загружайте автоматически все файлы из `docs/` или `skills/`. Они нужны, чтобы упростить поиск подходящего контекста, а не увеличить объём постоянных инструкций.

## Эталонные примеры

Эталонный пример — существующая реализация, которая отражает предпочтительный подход в проекте.

| Задача | Возможный пример |
|---|---|
| Операция API | `services/users/handlers/create-user/` |
| Миграция базы данных | `database/migrations/...` |
| Фоновая задача | `workers/example-job/` |
| Обработчик сообщений | `services/orders/consumers/example/` |
| Функциональность интерфейса | `apps/web/features/example/` |
| Инфраструктурный модуль | `infrastructure/services/example/` |

Отдавайте предпочтение реальной, поддерживаемой реализации вместо длинного текстового описания, если она лучше передаёт нужный подход.

## Сохранение знаний

Если агенту пришлось изучить много файлов, чтобы выяснить устойчивый архитектурный факт, подумайте о том, чтобы задокументировать результат.

Полезно сохранять сведения о взаимодействии сервисов, неочевидных границах ответственности, повторяющихся рабочих процессах, важных точках входа и специфичных для проекта ограничениях.

Не сохраняйте временные результаты отладки, очевидные детали реализации, дубликаты информации из основного источника или предположения.

## Чек-лист чистоты контекста

Периодически проверяйте:

- Остаётся ли AGENTS.md небольшим?
- Актуальны ли все указанные пути?
- Остаются ли эталонные примеры образцами для подражания?
- Есть ли устаревшие инструкции?
- Дублируются ли правила?
- Не попадают ли знания об отдельных сервисах в глобальный контекст?

## Совместимость с инструментами

Основной файл шаблона — `AGENTS.md`. Если инструмент ожидает другое имя файла или формат, адаптируйте или генерируйте нужную ему точку входа из того же источника, чтобы не поддерживать противоречащие друг другу копии.
