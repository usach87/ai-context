# Skills

Skills contain detailed instructions for **recurring, project-specific tasks**. They are optional.

## Create a skill when

- the workflow repeats;
- it requires non-obvious project knowledge;
- agents repeatedly rediscover the same steps;
- instructions are too detailed for global context;
- a repeatable validation sequence matters.

## Do not create a skill when

- the task is rare;
- a golden example is sufficient;
- it repeats global rules;
- the workflow is temporary or unstable.

A skill should answer:

1. When should it be used?
2. Where should the agent start?
3. What is the golden example?
4. Which constraints matter?
5. What is the smallest useful validation sequence?

Keep skills focused.
